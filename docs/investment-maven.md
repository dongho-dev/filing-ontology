## 1. 한 줄 요약

공시에서 달라진 것을 **내가 세운 가설에 비춰** 알려 주고, 내 판단과 이유를 기록해 나중에 돌아보게 하는 시스템. 판단과 매매는 사람이 합니다.

## 2. 메이븐에서 가져오는 것과 가져오지 않는 것 [정함]

메이븐은 여러 센서의 데이터를 한 상황판에 모으고, AI가 대상을 찾아내고, 사람이 결정하고, 결과가 다시 들어오는 군사용 의사결정 시스템으로 알려져 있습니다.

| 가져오는 것 | 이 레포에서 |
|---|---|
| 여러 자료를 한 상황판에 | 대시보드의 고정 화면 |
| 변화를 찾아냄 | 감시 조건과 알림 |
| 결정은 사람이 함 | 판단은 사용자가 내리고 기록함 |
| 결과가 다시 들어옴 | 판단을 나중에 돌아보는 기록 |

| 가져오지 않는 것 | 이유 |
|---|---|
| 속도 경쟁 | 이 도메인에서는 우선순위가 낮다. 실적이 나오면 주가는 몇 초에서 몇 분 안에 움직이므로 속도로는 이길 수 없고, 이 도구의 값은 빠짐없음과 일관성에 있다 |
| 시스템이 내는 추천 | "사라, 팔아라"는 투자 자문이다. 시스템은 사실과 내 기준 사이의 관계만 말한다 |
| 실행 | 매매 주문이나 증권 계좌 연동은 만들지 않는다 |

## 3. 고리 [안]

concept.md 16장의 여섯 단계에 "가설에 비춤"과 "돌아보기"를 더합니다.

| 단계 | 내용 | 지금 |
|---|---|---|
| 1. 들어옴 | 공시에서 값과 관계가 들어온다 | 있음 (손으로 돌림) |
| 2. 탐지 | 직전 값과 비교해 달라진 것을 찾는다 | 있음 |
| 3. 가설에 비춤 | 달라진 값이 내 가설의 어느 조건에 닿는지 판정한다 | 있음 (예시 가설 하나, `scripts/thesis.py`) |
| 4. 알림 | "어느 가설의 어느 조건이 어떻게 됐는지"를 근거와 함께 보여 준다 | 일부 (가설과 이어지지 않은 알림만 있음) |
| 5. 판단 | 사용자가 무엇을 하기로 했는지와 이유를 적는다 | 없음 (발언 조건의 판정 기록만 있음) |
| 6. 기록 | 판단과 값 검토·정정이 쌓인다 | 일부 (검토·정정·잇기만) |
| 7. 돌아보기 | 시간이 지난 뒤, 그때의 가설과 판단이 맞았는지 사용자가 적는다 | 없음 |

## 4. 온톨로지에 더할 대상 [안]

| 대상 | 뜻 | 주요 속성 |
|---|---|---|
| 가설 | 한 회사를 보는 이유를 한 문장으로 적은 것 | 회사, 문장, 만든 날, 상태(조건에서 계산) |
| 조건 | 가설이 성립하려면 지켜져야 하는 것. 값으로 판정할 수 있어야 한다 | 속한 가설, 지표, 종류(이상, 이하, 늘어남, 줄어듦), 기준값 |
| 판정 | 어느 기간의 값으로 조건을 비춘 결과 | 조건, 기간, 결과(지켜짐, 가까워짐, 깨짐, 판정 불가), 근거 값 |
| 판단 | 사용자가 내린 결정 | 날짜, 본 알림과 가설, 하기로 한 것(사용자가 쓴 말 그대로), 이유 |
| 돌아보기 | 판단을 나중에 평가한 것 | 판단, 날짜, 사용자가 적은 평가 |

- 가설의 상태는 사람이 고르지 않고 조건의 판정에서 나옵니다. 조건이 모두 지켜지면 "유지", 하나라도 가까워지면 "흔들림", 하나라도 깨지면 "깨짐", 판정할 값이 없으면 "판정 불가"입니다.
- 가설의 상태를 정하는 순서: 깨진 조건이 있으면 "깨짐", 아니면 가까워진 조건이 있으면 "흔들림", 아니면 판정하지 못한 조건이 있으면 "판정 불가", 모두 지켜지면 "유지"입니다. 판정 불가가 섞여 있으면 "유지"라고 말하지 않습니다.
- 회사의 최신 분기에 해당하는 값이 없으면 지난 분기 값으로 대신하지 않고 "판정 불가"로 둡니다.
- "가까워짐"은 조건마다 `near`로 정합니다. 기준값 조건은 기준까지 near 이내일 때, 늘어남·줄어듦 조건은 변화율이 near% 이내일 때입니다. `near`가 없으면 가까워짐 없이 지켜짐과 깨짐만 있습니다.
- 지금의 감시 조건 다섯 개(`ontology/monitors.json`)는 임의로 정한 것입니다. 가설이 들어오면 감시 조건은 가설의 조건에서 나옵니다.

## 5. 예시

**아래 가설은 틀을 보여 주려고 지어낸 것이며, 권고가 아닙니다.** 값은 2026-11-13 현재 대시보드에 있는 실제 값입니다.

> 가설: "네비우스는 수요가 공급을 넘는 동안 본다."

| 조건 | 기준 | 최신 값 (2026년 3분기) | 판정 |
|---|---|---|---|
| 수주 잔고가 직전 분기보다 늘어난다 | 늘어남 | 387억 달러, 직전 분기 대비 +3.2% | 지켜짐 |
| 최대 고객 비중이 40% 아래다 | 40% 이하 | 33% (Customer E), 직전 분기 24% | 가까워짐 |
| 회사가 가격이 오른다고 말한다 | 서한의 발언 | "GPU 시간당 가격이 2분기보다 평균 20% 넘게 올랐다"는 취지 | 지켜짐 (사람이 읽고 판정) |

이때 알림은 "가설의 조건 셋 중 둘은 지켜짐, 최대 고객 비중은 기준에 가까워짐"이 됩니다. 그다음에 무엇을 할지는 사용자가 정하고 이유를 적습니다.

세 번째 조건처럼 숫자가 아닌 발언에 기대는 조건은 자동으로 판정하지 않고 사람이 읽고 판정합니다. 구현에서는 사람의 판정 기록이 없는 동안 "판정 불가"로 나오고, 새 분기가 오면 다시 "판정 불가"로 돌아갑니다. 위 표의 "지켜짐"은 사람이 판정을 기록했을 때의 모습입니다.

이 예시는 `ontology/theses.json`에 들어 있고 대시보드의 "가설" 탭에서 볼 수 있습니다. 최대 고객 비중 조건은 `near`를 10%p로 두었습니다.

## 6. 원칙 [정함]

- 시스템은 사실과 내 기준 사이의 관계만 말합니다. 추천하지 않습니다.
- 없는 것은 모른다고 말합니다. 조건을 판정할 값이 없으면 "판정 불가"입니다.
- 속도보다 빠짐없음과 일관성이 먼저입니다. 반영이 몇 분에서 하루 늦어도 됩니다.
- 모든 판정에는 근거 값과 공시가 붙습니다.
- 판단과 돌아보기는 덧붙이기만 합니다. 지나간 판단을 고쳐 쓰지 않습니다.
- 매매 실행과 계좌 연동은 만들지 않습니다.

## 7. 센서 넓히기 [미정]

지금 센서는 공시 한 종류입니다. 넓힌다면 이 순서를 생각하고 있습니다.

| 자료 | 쓰임 | 주의 |
|---|---|---|
| 실적 보도자료, 주주 서한 | 이미 씀 | |
| 컨퍼런스콜 발언 | 경영진이 주제별로 한 말 | 공시가 아니므로 출처를 구분해 적는다 |
| 주가 | 돌아보기에서 "그 뒤 어떻게 됐는지"를 볼 때 | 조건의 기준으로는 쓰지 않는다 |
| 공시 밖 자료(요금표, 기사) | 가려진 고객 확인 등 | concept.md 8장의 "공시에 적힌 것만"을 바꾸는 결정이 먼저 필요하다 |

## 8. 만드는 순서 [안]

1. 가설과 조건을 정의 파일로 두고, 조건을 최신 값에 비춰 판정한다. **(2026-11-13 예시 가설로 구현)**
2. 알림에 "어느 가설의 어느 조건"인지를 붙인다. 감시 조건을 가설에서 나오게 바꾼다.
3. 판단 기록을 행동에 더한다.
4. 화면의 "자료 없음"을 "공시에 없음, 아직 안 읽음, 해당 없음"으로 나누고 "판정 불가"와 잇는다.
5. 새 공시를 자동으로 감지해 고리를 돌린다.
6. 돌아보기를 더한다.

## 9. 끝 기준 [안]

- 새 공시가 나왔을 때 손대지 않아도 가설의 상태가 갱신되고 알림이 뜬다.
- 알림에서 근거 공시까지 한 번에 간다.
- 한 분기 뒤에, 그때 무엇을 보고 어떤 판단을 했는지 기록에서 찾아 돌아볼 수 있다.

## 10. 정해야 할 것

| 정할 것 | 메모 |
|---|---|
| 첫 가설을 어느 회사에 대해 무엇으로 쓸지 | 사용자만 정할 수 있다 |
| "가까워짐"의 기준 | 조건마다 `near`로 두게 만들었다. 값을 얼마로 둘지는 가설을 쓸 때 정한다 |
| 발언에 기대는 조건을 어떻게 다룰지 | 사람이 판정하고 이유를 기록하게 만들었다 |
| 돌아보기를 언제 하게 할지 | 다음 분기 공시가 나올 때를 제안 |
