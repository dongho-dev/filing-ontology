# 고리(감시 → 영향 → 알림 → 행동 → 기록) 구현

- 상태: 완료 (첫 판, 커밋 전)
- 마지막 갱신: 2026-11-13 20:50

## 목표

팔란티어식 고리를 이 레포에서 작은 단위로 통째로 구현한다. 사용자 요청: "고리를 통째로 구현해줘 작은 단위에서." 도메인은 바꾸지 않는다(실제 데이터가 있고, 확인·정정·잇기가 다음 화면을 실제로 바꾸는 행동이라 고리가 닫힌다).

앞 작업: `progress/2026-11-13_1741_mvp-dashboard.md` (완료, main에 커밋·푸시됨 23e0e66).

## 설계 (정함)

| 단계 | 파일 | 내용 |
|---|---|---|
| 1. 들어옴 | 기존 `ontology/values_*.json` | 그대로 |
| 2. 감시 | `ontology/monitors.json`, `scripts/loop.py` | 회사별 최신 기간과 직전 기간을 비교해 조건에 걸리는지 본다 |
| 3. 영향 범위 | `scripts/loop.py` | `ontology/relations.json`과 "잇기" 기록을 따라간다. 연결이 없으면 "모름" |
| 4. 알림 | `ontology/alerts.json`, 대시보드 "알림" 탭 | 달라진 것, 근거, 영향 범위 |
| 5. 행동 | `scripts/serve.py`의 POST /api/action | 검토함(review), 값 정정(correct), 가려진 고객 잇기(link), 알림 닫기(dismiss) |
| 6. 기록 | `ontology/actions.jsonl`, 대시보드 "기록" 탭 | 행동이 쌓이고, 빌드할 때 값과 알림에 다시 반영된다 |

- 행동 대상 값의 열쇠: `company|metric|period_end`. 알림 id: `company|rule_id|period_end`.
- 서버는 표준 라이브러리 http.server, 127.0.0.1에만 연다. 서버 없이 열면(정적) 행동 버튼은 꺼진다.
- 좋고 나쁨의 색을 쓰지 않고 투자 판단을 하지 않는다.

## 결과와 남은 것

- 처음 걸린 알림 11건: 네비우스 2, 코어위브 4, 아이렌 2, 엔비디아 3.
- actions.jsonl에 실제 행동 2줄: 네비우스 고객 비중 정정(오늘 실제로 한 일), 코어위브 3분기 최대 고객 비중 검토함(메인이 원문 표에서 Customer B 30%를 확인했으므로 사실).
- 엔비디아의 "최대 고객이 바뀜" 알림은 원문 표현이 'three direct customers'에서 'one direct customer'로 바뀐 것이라 실제 고객 변화가 아닐 수 있다. 조건을 다듬어야 한다.
- 설계와 달라진 곳: 검토·정정은 text 값만 받는다. 정정 입력은 화면 단위(억 달러, %, MW). review와 dismiss는 이유 없이 바로 기록. 되돌리기 없음.
- 화면 캡처가 시간 초과로 실패해 배치와 모양은 눈으로 확인하지 못했다(동작은 DOM으로 확인). 사용자 화면 피드백 필요.
