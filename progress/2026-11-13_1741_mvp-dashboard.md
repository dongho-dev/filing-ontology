# MVP 비교 대시보드

- 상태: 완료 (첫 판)

## 목표

네비우스, 코어위브, 아이렌, 엔비디아 네 회사의 지표를 한 화면에서 나란히 보는 대시보드를 만든다. 숫자마다 근거(문서와 위치)를 붙인다. 사용자 요청: "엔비디아까지만 포함해서 ㄱㄱ" (고객사는 이번 범위에서 뺀다).

구상은 `docs/concept.md` 13·14장.

## 단계

1. [완료] 실행 환경과 SEC 접속 확인
2. [완료] 회사·지표 정의 파일 (`ontology/companies.json`, `ontology/metrics.json`)
3. [완료] 코어위브·아이렌·엔비디아 재무 숫자 (`scripts/fetch_sec.py`, `scripts/build_values.py` → `ontology/values_xbrl.json`, 값 90개)
4. [완료] 네비우스(6-K)와 글 속 지표, 엔비디아 공급 관계 (`scripts/merge_text.py` → `ontology/values_text.json` 값 47개, `ontology/relations.json` 관계 3개, 근거 문장 50건 원문 일치)
5. [완료] 대시보드 화면 (`scripts/build_dashboard.py` → `dashboard/data.js`, `dashboard/index.html`)
6. [완료] 화면 확인(localhost:8765, 콘솔 오류 없음, 칸을 누르면 근거 표가 나옴)

7. [완료] 화면을 고정 화면과 질의 화면으로 나눔 (`views/nbis-pricing.json`, 인용 7건 원문 일치, 구상 문서 15장)

## 결정한 것

- SEC 요청의 User-Agent는 `.env`의 SEC_USER_AGENT에서 읽는다(없으면 `research-script/0.1`, 이 값으로는 `data.sec.gov`만 된다).
- `.gitignore`가 `/data/`를 빼므로 내려받은 원본은 `data/raw/`에, 커밋할 정의와 값은 `ontology/`에 둔다.
- 파이썬 3.12, 표준 라이브러리만 쓴다.
- 구조화 데이터의 항목 여러 개를 앞에 적힌 순서로 합쳐 쓴다(같은 기간에 값이 다르면 앞의 것, 알림 출력). 아이렌이 총매출 항목을 중간에 바꿔서 필요했다.
- 누적으로만 보고되는 값(현금흐름표, 4분기)은 누적 값의 차이로 분기 값을 구하고, 근거에 두 공시를 모두 적는다.
- 화면에서 오르내림에 좋고 나쁨의 색을 입히지 않는다(판단을 하지 않는다는 원칙).
- 글에서 뽑은 값은 `ontology/values_text.json`, 관계는 `ontology/relations.json`에 두면 `build_dashboard.py`가 읽는다. 근거 문장은 `scripts/check_quotes.py`로 원문과 글자 그대로 맞는지 검사한다.

## 막힌 것

- 없음. SEC 본문 접근은 사용자가 이메일 사용을 허락해 풀렸다(2026-11-13). 값은 `.env`의 SEC_USER_AGENT에만 있고 커밋되지 않는다. SEC 요청은 `scripts/sec_http.py`를 거친다.

## 검토하며 고친 것

- 코어위브 10-Q의 "undelivered" 전력 4건은 계약 전력 총량이 아니라서 뺐다. 보도자료(8-K)의 "total contracted power"만 쓴다.
- 서브에이전트가 네비우스 2026년 3분기에 "10% 이상 고객 없음"이라고 보고했으나 표를 직접 보니 Customer E 33%였다(열을 잘못 읽음). `merge_text.py`가 표에서 다시 읽어 넣는다.
- 네비우스 전력 값은 분기 말이 아니라 발표일 기준이다. 화면에 날짜를 따로 적는다.
- 확인: 네비우스 2025년 네 분기 매출의 합(529.8)이 20-F의 연간 매출과 같다.
